# 从零安装与设备接入

本文把本项目在 Wayland 桌面上的 Android 环境准备、Waydroid 兼容性处理和上层视觉自动化接入整理成可迁移步骤。

目标读者是希望在自己的 Linux Wayland、Windows 或真机环境中运行本项目的开发者。文中的 Waydroid 章节是可选的；项目真正依赖的是 **在线且已授权的 ADB 设备**。

## 先看结论

项目分成两层：

```text
设备适配层：ADB 截图、无障碍树、Activity、点击、滑动、输入
业务编排层：元宝页面识别、每日任务状态机、兑换和完成断言
```

因此有两种运行方式：

| `ANDROID_DEVICE` | 运行方式 | 是否调用 Waydroid |
| --- | --- | --- |
| `auto` | 自动发现 Waydroid IP，按需启动会话，成功后停止会话 | 是 |
| `emulator-5554` 等本地序列号 | 使用已经启动的 Android 模拟器 | 否 |
| `<USB_SERIAL>` | 使用已经授权的 USB 真机 | 否 |
| `<主机>:5555` | 使用 ADB TCP 设备或远程模拟器 | 否 |

显式设备模式会通过 `adb -s <设备序列号>` 执行所有动作，并通过标准 `adb shell am start` 启动应用，不依赖 `waydroid` 命令。当前业务编排是针对腾讯元宝的示例，不代表已经支持任意应用的任务语义。

## 1. 环境要求

### Waydroid 路线

- 64 位 Linux，建议 Ubuntu 24.04/26.04 或较新的 Debian/Ubuntu 衍生版。
- Python 3.10 或更高版本（脚本使用现代类型标注语法）。
- 当前登录会话必须是 Wayland：

  ```bash
  printf 'XDG_SESSION_TYPE=%s\n' "$XDG_SESSION_TYPE"
  printf 'WAYLAND_DISPLAY=%s\n' "$WAYLAND_DISPLAY"
  ```

  预期 `XDG_SESSION_TYPE=wayland`，并且 `WAYLAND_DISPLAY` 非空。KDE Plasma 应选择 Plasma Wayland 会话。

- 内核需要支持 Waydroid 所需的 binder 接口；发行版内核通常已经提供。若启动失败，先查看：

  ```bash
  uname -a
  grep -E 'CONFIG_ANDROID_BINDER|CONFIG_ANDROID_ASHMEM' "/boot/config-$(uname -r)" 2>/dev/null || true
  ls -l /dev/binder* /dev/anbox-* 2>/dev/null || true
  ```

- 至少预留数 GB 磁盘空间。Waydroid、WebView 和视觉模型同时运行时会产生明显内存压力；4 GiB 是本机的限制值，不是通用推荐值。

### 非 Waydroid 路线

- 已安装 Android SDK Platform Tools，并且 `adb` 在 `PATH` 中：

  ```bash
  adb version
  adb devices -l
  ```

  Platform Tools 可从 [Android 官方下载页](https://developer.android.com/tools/releases/platform-tools) 获取；Windows 用户将解压后的目录加入 `PATH`，或在该目录中运行 PowerShell 命令。

- 模拟器已经启动，或真机已经打开开发者选项、USB 调试并完成 RSA 授权。
- 设备上已安装目标应用，且屏幕尺寸、系统语言和 WebView 行为适合你的测试。
- Windows 用户不需要安装 Waydroid；使用 Android Studio Emulator、MuMu 等能提供 ADB 的模拟器即可。脚本本身使用标准 ADB 命令，Windows 下可用 PowerShell 运行。

## 2. 在 Ubuntu Wayland 安装 Waydroid

以下命令参考 Waydroid 官方安装文档。Ubuntu 26.04 使用 `resolute`，官方仓库脚本当前可以识别该代号；如果发行版或仓库状态发生变化，应先查看官方页面再继续。

### 2.1 安装依赖和软件源

先安装基础工具：

```bash
sudo apt update
sudo apt install -y curl ca-certificates git unzip desktop-file-utils lzip adb python3 python3-venv
```

推荐先下载并检查软件源脚本，再执行：

```bash
curl -fsSL https://repo.waydro.id -o /tmp/waydroid-repo.sh
sed -n '1,220p' /tmp/waydroid-repo.sh
sudo bash /tmp/waydroid-repo.sh
sudo apt update
sudo apt install -y waydroid
```

如果自动识别发行版失败，使用当前系统代号作为第一个参数。Ubuntu 26.04 的代号是 `resolute`：

```bash
sudo bash /tmp/waydroid-repo.sh resolute
sudo apt update
sudo apt install -y waydroid
```

不要把仓库脚本、Android 镜像或第三方 ARM 翻译库提交到本项目；它们有各自的发布和许可条款。

### 2.2 初始化镜像

不需要 Google 服务时使用体积较小的 VANILLA 镜像：

```bash
sudo waydroid init -s VANILLA
```

确实需要 Play 服务时才选择 GAPPS：

```bash
sudo waydroid init -s GAPPS
```

GAPPS 会增加磁盘、内存和登录兼容性变量。腾讯应用不一定需要 GAPPS；是否安装应由被测应用的依赖决定。

### 2.3 启动容器、会话和窗口

Waydroid 官方要求容器以 root 运行，会话以当前桌面用户运行：

```bash
sudo waydroid container start
waydroid session start
waydroid show-full-ui
```

另开终端确认状态：

```bash
waydroid status
```

预期同时看到 `Container: RUNNING` 和 `Session: RUNNING`。关闭时使用：

```bash
waydroid session stop
sudo waydroid container stop
```

## 3. 手机窗口、语言、时区和 ADB

### 3.1 设置多窗口和分辨率

本项目使用 750x1333 的手机比例，低于 1440 高度的宿主屏幕，便于观察和截图。Waydroid 官方将这些设置作为可重启会话生效的属性：

```bash
waydroid prop set persist.waydroid.multi_windows true
waydroid prop set persist.waydroid.width 750
waydroid prop set persist.waydroid.height 1333
waydroid session stop
waydroid session start
```

实际尺寸以设备报告为准：

```bash
adb -s <WAYDROID_IP>:5555 shell wm size
```

### 3.2 连接 ADB

Waydroid 的 IP 会随容器重启变化，不要把本机某一次的 IP 固定写进项目：

```bash
waydroid status
adb connect <WAYDROID_IP>:5555
adb -s <WAYDROID_IP>:5555 get-state
```

预期最后一条输出 `device`。当 `adb devices` 中存在离线的 `emulator-5554` 或多个设备时，始终使用 `-s`，不要执行无目标的 `adb shell`。

设置简体中文和北京时间：

```bash
adb -s <WAYDROID_IP>:5555 shell settings put system system_locales zh-CN
adb -s <WAYDROID_IP>:5555 shell settings put global auto_time_zone 0
adb -s <WAYDROID_IP>:5555 shell setprop persist.sys.timezone Asia/Shanghai
adb -s <WAYDROID_IP>:5555 shell settings get system system_locales
adb -s <WAYDROID_IP>:5555 shell getprop persist.sys.timezone
```

不同 Android 镜像对 locale 命令的支持略有差异；如果 `system_locales` 没有生效，使用系统设置界面完成一次设置，然后重新读取属性确认。

## 4. ARM/ARM64 APK 适配

Waydroid 在 x86_64 主机上可以安装很多 APK，但 APK 内含的 ARM 原生库需要二进制翻译层。官方 Waydroid 文档把 `waydroid_script` 列为社区项目；翻译库不是 Waydroid 本体，也不应打包进本仓库。

### 4.1 识别 APK 架构

```bash
unzip -l app.apk | rg 'lib/(arm64-v8a|armeabi-v7a|x86_64|x86)/'
```

如果只有 `arm64-v8a`/`armeabi-v7a` 而主机容器是 x86_64，需要翻译层。物理 ARM64 真机不需要这一步；部分 Windows 模拟器已经自带 ARM 翻译，也不应重复安装。

### 4.2 安装一个翻译层

```bash
git clone https://github.com/casualsnek/waydroid_script.git
cd waydroid_script
python3 -m venv venv
venv/bin/python -m pip install -r requirements.txt
```

AMD 主机可以先按该项目文档尝试 `libndk`：

```bash
sudo venv/bin/python3 main.py install libndk
```

如果特定应用只兼容另一种实现，先卸载当前实现，再单独测试 `libhoudini`：

```bash
sudo venv/bin/python3 main.py uninstall libndk
sudo venv/bin/python3 main.py install libhoudini
```

两种翻译层不要同时安装。安装或切换后重启容器和会话，再检查：

```bash
adb -s <WAYDROID_IP>:5555 shell getprop ro.product.cpu.abilist
adb -s <WAYDROID_IP>:5555 shell getprop ro.dalvik.vm.native.bridge
adb -s <WAYDROID_IP>:5555 shell getprop ro.ndk_translation.version
```

本机历史配置使用过 `libhoudini.so`；这只是一次成功的兼容性记录，不应推导为所有 AMD 机器的最佳选择。不同应用的原生库、反模拟器检测和硬件服务依赖都可能改变结果。

## 5. 可选：伪装为常见手机型号

设备伪装不是运行本项目的必要条件，也不能绕过所有厂商校验、Play Integrity 或反模拟器检测。只有在被测应用明确因为设备型号拒绝运行时，才在隔离测试环境中尝试。

本机使用过小米 13（`fuxi`/`2211133C`）这一组属性：

```bash
waydroid prop set ro.product.brand Xiaomi
waydroid prop set ro.product.manufacturer Xiaomi
waydroid prop set ro.product.model 2211133C
waydroid prop set ro.product.device fuxi
waydroid prop set ro.product.name fuxi
waydroid prop set ro.build.display.id 'TKQ1.221114.001 V14.0.31.0.TMCCNXM'
waydroid prop set ro.build.fingerprint 'Xiaomi/fuxi/fuxi:13/TKQ1.221114.001/V14.0.31.0.TMCCNXM:user/release-keys'
```

验证属性：

```bash
adb -s <WAYDROID_IP>:5555 shell getprop ro.product.model
adb -s <WAYDROID_IP>:5555 shell getprop ro.product.device
```

如果应用在伪装后出现新的崩溃，恢复 Waydroid 初始化时生成的属性备份，或者重新初始化干净镜像。不要把伪装值当作通用默认值。

## 6. 安装和启动 Android 应用

Waydroid 官方支持：

```bash
waydroid app install /path/to/app.apk
waydroid app list
waydroid app launch com.example.app
```

本项目示例使用腾讯元宝和应用宝时，可以按自己取得的官方 APK 安装；仓库不分发 APK：

```bash
waydroid app install /path/to/应用宝.apk
waydroid app install /path/to/元宝.apk
waydroid app launch com.tencent.android.qqdownloader
waydroid app launch com.tencent.hunyuan.app.chat
```

如果下载的是拆分 APK（多个 `base.apk`/架构 APK），不要只安装其中一个文件；使用对应设备的标准 ADB 一次性安装：

```bash
adb -s <DEVICE> install-multiple -r /path/to/base.apk /path/to/split_config.arm64_v8a.apk
```

不同发布渠道的拆分文件名称和数量可能不同，必须把同一版本的全部必要 split 一起传入。

Waydroid 安装应用后通常会在当前桌面用户的应用菜单中生成入口，例如元宝和应用宝会分别生成 `waydroid.com.tencent.hunyuan.app.chat.desktop` 与 `waydroid.com.tencent.android.qqdownloader.desktop`。如果 KDE 应用菜单没有立即显示新入口，可以刷新桌面数据库：

```bash
update-desktop-database "$HOME/.local/share/applications" 2>/dev/null || true
```

也可以直接从终端启动应用。`waydroid app launch` 只适合 Waydroid；下面的标准 ADB 方式适合所有设备：

ADB 设备也可以使用标准命令：

```bash
adb -s <DEVICE> install -r /path/to/app.apk
adb -s <DEVICE> shell monkey -p com.example.app 1
```

本项目的每日任务脚本会先用 `cmd package resolve-activity` 找到目标应用的启动 Activity，再用标准 ADB `am start -n` 启动，不依赖 Waydroid。冷启动时 ADB 变为 `device` 不代表 Android 包管理器已经完成启动，脚本会在有界时间内重试 Activity 解析；手动验证时也可以使用：

```bash
adb -s <DEVICE> shell monkey -p com.tencent.hunyuan.app.chat 1
```

因此显式连接 Windows 模拟器或真机时，不需要安装 Waydroid；只需确保 APK 已安装、ADB 状态为 `device`，并且设备允许截图和输入事件。

## 7. 本次元宝登录崩溃的诊断和修复

这一节是针对元宝版本和 Waydroid 组合的案例，不保证适用于其他应用。先区分网络、应用渲染进程和宿主机内存三个问题，不要看到“断网”文案就直接修改代理。

### 7.1 先验证网络事实

```bash
waydroid status
adb -s <WAYDROID_IP>:5555 shell ip route
adb -s <WAYDROID_IP>:5555 shell getprop net.dns1
adb -s <WAYDROID_IP>:5555 shell ping -c 1 yuanbao.tencent.com
```

宿主机和容器能够解析域名、访问腾讯主页或验证码页面并返回 HTTP 200 时，说明基础链路已经可用。Clash/Mihomo 的 `TUN + DIRECT` 表示流量被 TUN 接管后按规则直连，不等于网络被关闭。应先保留现有规则，再查看应用进程日志。

### 7.2 HIDL allocator `SIGABRT` 或容器启动失败

本机早期出现过：

```text
android.hidl.allocator@1.0-service
Signal: 6 (ABRT)
Control Group: /lxc.payload.waydroid
```

它是容器系统服务的 coredump，不能直接等同于元宝崩溃或宿主机 OOM。先保存状态和日志：

```bash
waydroid status
waydroid log > /tmp/waydroid.log
sudo journalctl -u waydroid-container --no-pager -n 300 > /tmp/waydroid-container.log
```

确认内核节点和配置：

```bash
ls -l /dev/binder* /dev/anbox-* 2>/dev/null || true
rg -n 'binder|protocol|auto_adb' /var/lib/waydroid/waydroid.cfg
```

本机最终使用的兼容性配置为：

```ini
[waydroid]
auto_adb = True
binder = anbox-binder
vndbinder = anbox-vndbinder
hwbinder = anbox-hwbinder
binder_protocol = aidl3
service_manager_protocol = aidl3
```

只有当对应 `/dev/anbox-*` 节点确实存在、且日志表现与本案例相似时，才备份后通过 `sudoedit /var/lib/waydroid/waydroid.cfg` 对照设置。不要把本机节点名称盲目复制到不兼容的内核。修改后重启：

```bash
waydroid session stop
sudo waydroid container stop
sudo waydroid container start
waydroid session start
```

### 7.3 元宝登录最后一步无限转圈

本机原始日志反复出现：

```text
MultiProcess: Recovering https://yuanbao.tencent.com/e/login/...
ActivityManager: Start proc ...:privileged_process0/1/2
ActivityManager: Process ...:privileged_processN ... has died
```

对应 X5/TBS Chromium 子进程触发 `SIGSYS (Bad system call)`，主进程不断恢复登录 URL。验证码能发送、未登录首页能打开，并不能排除这个渲染兼容性问题。

抓取应用和 WebView 日志：

```bash
adb -s <DEVICE> shell dumpsys webviewupdate
adb -s <DEVICE> logcat -d -v threadtime | rg 'WebViewFactory|MultiProcess|privileged_process|SIGSYS|com.tencent.hunyuan.app.chat'
```

本机最终采用的是元宝私有偏好开关，让它选择系统 WebView。先启动过一次元宝以创建数据目录，然后停止元宝和会话。不要假定数据目录路径；从 `/var/lib/waydroid/waydroid.prop` 的 `waydroid.host_data_path` 读取当前实例路径。

```bash
APP_PACKAGE=com.tencent.hunyuan.app.chat
WAYDROID_DATA="$(sudo awk -F= '$1 == "waydroid.host_data_path" {print substr($0, index($0, "=") + 1)}' /var/lib/waydroid/waydroid.prop)"
if [ -z "$WAYDROID_DATA" ]; then
  echo "没有从 waydroid.prop 找到 waydroid.host_data_path"
  exit 1
fi
APP_DATA="$WAYDROID_DATA/data/$APP_PACKAGE"
PREF_DIR="$APP_DATA/shared_prefs"

sudo test -d "$APP_DATA" || { echo "应用数据目录不存在，请先启动一次元宝"; exit 1; }
waydroid session stop
sudo cp -a "$PREF_DIR/system_core_prefs.xml" \
  "$PREF_DIR/system_core_prefs.xml.before-system-webview" 2>/dev/null || true

printf '%s\n' \
  "<?xml version='1.0' encoding='utf-8' standalone='yes' ?>" \
  '<map>' \
  '    <boolean name="system_core_enabled" value="true" />' \
  '</map>' | sudo tee "$PREF_DIR/system_core_prefs.xml" >/dev/null

OWNER="$(sudo stat -c '%u:%g' "$APP_DATA")"
sudo chown "$OWNER" "$PREF_DIR/system_core_prefs.xml"
sudo chmod 660 "$PREF_DIR/system_core_prefs.xml"
```

重新启动并验证：

```bash
sudo waydroid container start
waydroid session start
adb connect <WAYDROID_IP>:5555
adb -s <WAYDROID_IP>:5555 shell dumpsys webviewupdate
adb -s <WAYDROID_IP>:5555 logcat -d -v threadtime | rg 'WebViewFactory|privileged_process|SIGSYS'
```

预期看到 `com.android.webview` 被加载，不再出现新的元宝 X5 `privileged_process`/`SIGSYS` 循环。该开关是应用私有、版本相关的兼容性处理；元宝更新后可能重写偏好、改变 TBS 代码或不再识别该键，届时必须重新抓日志确认，不能假设修复永久有效。

### 7.4 内存压力和 4 GiB 限制

Waydroid Android 进程位于 LXC cgroup `/sys/fs/cgroup/lxc.payload.waydroid`。只给 `waydroid-container.service` 设置 systemd `MemoryMax` 不一定能限制 Android 进程。本机为了避免视觉模型和 Chromium 同时运行时挤占宿主机，给 LXC 配置了 4 GiB 上限。

这是可选的机器级调优，不应作为所有开发者的默认值。执行前停止会话和容器，保存配置：

```bash
waydroid session stop
sudo waydroid container stop
sudo cp -a /var/lib/waydroid/lxc/waydroid/config \
  "/var/lib/waydroid/lxc/waydroid/config.before-memory-limit-$(date +%Y%m%d%H%M%S)"
sudoedit /var/lib/waydroid/lxc/waydroid/config
```

在配置文件中加入一行（数值为字节）：

```text
lxc.cgroup2.memory.max = 4294967296
```

启动后检查：

```bash
cat /sys/fs/cgroup/lxc.payload.waydroid/memory.max
cat /sys/fs/cgroup/lxc.payload.waydroid/memory.events
```

如果 `oom_kill` 增加，说明上限太低或同时运行的应用过多。任务失败时项目默认保留 Waydroid 现场，便于查看日志；只有完整任务、兑换和奖励使用断言都通过后，`STOP_WAYDROID_AFTER_RUN=true` 才会停止会话。

## 8. 配置并运行本项目

### 8.1 Linux（Waydroid 或显式 ADB）

建议把仓库放在 `~/auto-daily`，这样可以直接使用文末的 systemd 单元；放在其他目录也可以，只需把单元中的项目路径改成实际位置。在项目目录执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
```

编辑 `.env`，至少填写本地视觉模型端点密钥。路径默认是项目内的相对路径，不要改成其他开发者无法访问的绝对路径：

```dotenv
MODEL_ID=gemini-3.7-flash
BASE_URL=http://localhost:7860/v1
LOCAL_LLM_API_KEY=请填入本地端点密钥
ANDROID_DEVICE=auto
STOP_WAYDROID_AFTER_RUN=true
TEST_IMAGE_PATH=测试题目.png
PROMPT_PATH=每日任务提示词.md
STATE_PATH=.yuanbao_daily_state.json
```

运行一轮：

```bash
.venv/bin/python 元宝每日任务.py --once
```

`ANDROID_DEVICE=auto` 只在 Linux Waydroid 路线使用：脚本检查 Waydroid 状态，必要时启动会话，发现当前 IP 后连接 ADB，最后启动元宝。

macOS、WSL 或没有 Waydroid 的 Linux 主机不要使用 `ANDROID_DEVICE=auto`；请按下一节的方式填写已经在线的模拟器、真机或 TCP ADB 序列号。这样上层脚本仍可复用，但不会尝试调用不存在的 Waydroid 命令。

### 8.2 Windows PowerShell 或其他 ADB 主机

安装 Python 3.10 或更高版本、ADB 和目标应用。先确认设备：

```powershell
adb devices -l
adb -s emulator-5554 get-state
```

创建环境并运行：

```powershell
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

将 `.env` 中的设备改成模拟器序列号、USB 序列号或 TCP 地址：

```dotenv
ANDROID_DEVICE=emulator-5554
```

TCP 设备先连接：

```powershell
adb connect 192.0.2.10:5555
```

然后运行：

```powershell
.venv\Scripts\python 元宝每日任务.py --once
```

显式设备模式不会执行 `waydroid status`、`waydroid session start` 或 `waydroid session stop`。失败时检查 `adb -s <DEVICE> get-state`、应用是否已安装、设备是否允许截图和输入，以及本地模型端点是否可访问。

### 8.3 真机

```bash
adb devices -l
adb -s <USB_SERIAL> install -r app.apk
```

第一次连接要在手机上确认 RSA 指纹。真机通常是 ARM64，不需要 ARM 翻译；但元宝登录、WebView 版本、系统权限和界面尺寸可能与 Waydroid 不同，不能把 Waydroid 的设备伪装和 WebView 偏好直接套到真机。

## 9. 每日定时任务

仓库中的 `yuanbao-daily.service` 和 `yuanbao-daily.timer` 是 Linux 用户级 systemd 示例，按 `Asia/Shanghai` 每日 05:00 运行。它们不要求必须使用 Waydroid：

- `ANDROID_DEVICE=auto` 时，服务会按 Waydroid 生命周期运行。
- 显式设置 `ANDROID_DEVICE=<ADB序列号>` 时，服务不会关闭外部模拟器或真机；设备必须由外部系统保持在线。

安装到用户 systemd：

```bash
mkdir -p ~/.config/systemd/user
cp yuanbao-daily.service yuanbao-daily.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now yuanbao-daily.timer
systemctl --user list-timers yuanbao-daily.timer
```

查看日志：

```bash
journalctl --user -u yuanbao-daily.service -e
```

Windows 没有这组 systemd 单元，应使用任务计划程序或其他调度器调用同一条 Python 命令，并提前启动模拟器、连接 ADB 和本地模型端点。

## 10. 验证清单

每次迁移到新主机后按顺序验证：

```bash
adb -s <DEVICE> get-state
adb -s <DEVICE> shell wm size
adb -s <DEVICE> shell settings get system system_locales
adb -s <DEVICE> shell getprop persist.sys.timezone
adb -s <DEVICE> shell dumpsys webviewupdate
adb -s <DEVICE> shell pm path com.tencent.hunyuan.app.chat
```

项目级检查：

```bash
.venv/bin/python -m unittest -v test_元宝每日任务.py
.venv/bin/python -m py_compile 元宝每日任务.py 视觉安卓代理.py test_元宝每日任务.py
```

确认以下事实后再运行完整任务：

1. ADB 状态是 `device`，不是 `offline`。
2. `wm size` 返回的尺寸与模型提示和窗口实际一致。
3. 元宝已安装并能手动进入主页。
4. 登录流程已经完成，或你明确知道新设备需要人工登录。
5. 本地视觉端点的模型 ID、Base URL 和密钥有效。
6. 测试图片不包含个人信息，且可以被拍题/OCR 识别。

## 11. 常见误区

| 现象 | 首先检查什么 | 不要直接做什么 |
| --- | --- | --- |
| `adb device offline` | IP 是否变化、RSA 是否授权、是否选错序列号 | 不要使用无目标 `adb` 命令 |
| 页面显示断网 | DNS、网关、HTTP 返回、应用进程日志 | 不要先关闭 TUN 或随意改代理规则 |
| 首页正常、登录回调转圈 | WebView provider、X5 子进程和 `SIGSYS` | 不要只增加等待时间 |
| HIDL allocator ABRT | binder 节点、Waydroid 日志和内核配置 | 不要把一次 coredump 当作 OOM 结论 |
| ARM APK 安装成功但打不开 | APK `lib/` ABI、翻译层状态 | 不要同时安装 libndk 和 libhoudini |
| 任务重复点击 | 页面后置条件、Activity、UI 树是否变化 | 不要仅把 `MAX_STEPS` 调得更大 |
| 宿主机内存被杀 | Waydroid cgroup、Chromium 并发和截图进程 | 不要盲目把上限设成 4 GiB |

## 12. 开源和安全边界

- `.env`、访问密钥、手机号、验证码、二维码、Cookie、Token、真实登录日志和含个人信息的截图不应提交到 Git。
- `测试题目.png` 只是脱敏示例；替换时保持同样的隐私要求。
- ARM 翻译库、GApps、目标 APK 和第三方模拟器拥有各自的许可证，本仓库不重新分发它们。
- 元宝私有 WebView 偏好是针对特定版本的兼容性诊断结果，可能随应用更新失效；开源时应把它描述为“可选故障排查”，不要宣传成永久破解或通用补丁。
- 设备伪装可能影响应用条款、风控和完整性校验，只在你有权测试的账号和设备上使用。
